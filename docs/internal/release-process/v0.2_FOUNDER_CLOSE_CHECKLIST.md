### 1.7 — Fix chaos J3 FileExistsError leak (v4.1 §6.4 violation, pre-sprint blocker #6)

- **Why it matters (NEW critical finding)**: `tests/chaos/test_chaos_smoke.py` Scenario J3 (disk-full mid-materialize) currently leaks raw `FileExistsError` to user-facing output. Per `docs/specs/nucleus_architecture_v4.1.md` §6.4 + `AGENTS.md` §11.7 ("the #1 release blocker discipline"), every external exception MUST translate to a `NucleusError` subclass; user-facing strings MUST NOT contain external classnames. **Shipping v0.2.0 with this leak violates Hard Constraint discipline** even though the governance script (`scripts/dagster_leak_check.py`) does not catch it (script targets Dagster classnames only, not stdlib `*Error`).
- **Root cause**: `src/nucleus/coordination/asset_materialization.py:352` does `Path.mkdir(parents=True, exist_ok=False)` inside a try-block that does NOT wrap with `translate()`. The existing pattern at line 204 of the same file IS wrapped — this is a missed-spot rather than a design gap.
- **Recommendation**:
  1. Wrap the `mkdir(parents=True, exist_ok=False)` call in `translate()` per existing pattern at `asset_materialization.py:204`.
  2. Add new error code `NE5018 RaceConditionDuringWrite` to `src/nucleus/errors.py` (slot 5018 is currently unused per `scripts/check_error_codes.py`).
  3. Re-run J3: `pytest tests/chaos/test_chaos_smoke.py::test_j3_disk_full -v` (expect: `NE5018: RaceConditionDuringWrite during asset materialization` in user output, no `FileExistsError`).
  4. **Follow-up issue (post-tag, do NOT block on)**: extend `scripts/dagster_leak_check.py` to flag any stdlib `*Error` classname in user-facing strings (regex `\b[A-Z]\w*Error\b`). Tracked as a v0.2.1 / v0.3 governance hardening item.
- **Estimated time**: **20 min** (1-line wrap + 6-line `errors.py` addition + targeted pytest re-run).
- **Files affected**:
