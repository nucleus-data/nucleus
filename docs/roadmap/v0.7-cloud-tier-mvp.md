# v0.7 — Cloud Tier MVP

> **Codename**: Cloud Tier MVP
> **Target**: 2027 Q2 (Month 28-36 of founder's timeline; gated on Mo 24 decision gate)
> **LOC ceiling**: 24,000 (start of phase: ~16,000 from v0.5)
> **Persona**: Startup data team + platform engineering teams
> **Theme**: Give users a hosted on-ramp. Everything still Iceberg-portable. Single-tenant managed service as the first commercial tier.

---

## Theme: "Give Users a Hosted On-Ramp"

v0.7 ships Nucleus Cloud — a managed service where the founder operates the infrastructure and users pay per seat/usage. Everything Nucleus produces remains Iceberg-portable; users can graduate to any other Iceberg catalog at any time.

**The cloud tier is NOT**:
- Multi-tenant SaaS at hyperscale (that's v2.0 territory, and we yield to giants there)
- A lock-in mechanism (Iceberg portability is Mode 1 yield-to-giants)
- An AI platform or model hosting service

---

## Architecture Decision: Single-Tenant First

Per `docs/specs/nucleus_architecture_v4.1.md` Appendix B Q1 (answered):

> **Multi-tenant for v1.0 Cloud launch.** Single-tenant tier becomes Enterprise upsell in v1.5+ for regulated industries.
>
> Rationale: $20/seat startup beachhead pricing requires shared infrastructure economics. Multi-→single retrofit is easy; single-→multi retrofit is a nightmare.

**Propagation**:
- `tenant_id` propagated in `ctx` from v0.7 onward
- Iceberg buckets scoped: `s3://nucleus-tenant-{id}/`
- PostgreSQL schema per tenant (catalog metadata)
- Dedicated DuckDB process per query session

## Components

### 1. Control Plane (managed by Nucleus)

- Project provisioning API: `POST /v1/projects` creates a new Nucleus project in the cloud
- Catalog service: Lakekeeper or Polaris instance per tenant (v4.1 §5.7 dual-track default)
- Storage provisioning: S3 bucket per tenant (auto-provisioned on project create)
- Secrets management: AWS Secrets Manager or Vault for source credentials

**What stays OSS**: everything in `src/nucleus/`. The control plane is a thin operational layer around the OSS core, not new proprietary capabilities.

### 2. Agent Runtime (cloud-hosted execution)

- Cloud `nucleus run` — executes materializations on managed compute (no local Docker needed)
- Dagster runs on managed compute; user code is synced from their project repo
- Output: materialized Iceberg tables in tenant's S3 bucket

### 3. Billing Meter

- Per-asset-run cost tracked (CPU-seconds, S3 GETs + PUTs, AI tokens)
- Cost Meter MVP from v0.5 becomes billing-grade in v0.7
- Invoice via Stripe (or equivalent payment provider)
- `NUCLEUS_BILLING_ENABLED=1` env var gates all billing-specific paths

### 4. OIDC Federation (Auth)

Per `docs/specs/nucleus_architecture_v4.1.md` §15.1 + ADR-010:

- Nucleus Cloud delegates auth to user's OIDC provider (GitHub, Google, Okta, Azure AD)
- Never stores passwords
- SAML federation for enterprise (v1.5+; v0.7 is OIDC only)
- JWTs scoped per tenant; short-lived tokens

### 5. CLI Cloud Mode

```bash
nucleus login --cloud    # OIDC device flow
nucleus run <asset>      # executes in cloud if cloud project active
nucleus query <sql>      # queries cloud catalog
```

Smooth handoff: local-first by default; `nucleus login --cloud` switches to cloud mode. Toggle back with `nucleus logout`.

| Component | OSS | Commercial |
|---|---|---|
| `ctx` SDK + `@nucleus.asset` | ✅ forever | — |

| Local `nucleus up` stack | ✅ forever | — |

## License and Distribution

- Core OSS: Apache 2.0 forever (per `docs/specs/nucleus_architecture_v4.1.md` §D3 and ADR-002)
- Cloud service: proprietary operational layer on top of Apache 2.0 core
- No BSL, SSPL, or Commons Clause — we maintain the "friendly to giants" principle

## Go/No-Go Gate

- Mo 24 decision gate (ADR-002 §8.3) must pass before v0.7 work starts
- PoC: cloud control plane E2E — project provision → run asset → query result in <5 min (# NEEDS VERIFICATION — target to be refined)
- All OSS governance scripts still EXIT 0
- Security review: OIDC flow reviewed by at least one external security engineer

---

## Non-Goals for v0.7

- Multi-tenant SaaS (v2.0+)
- Self-hosted cloud (users run their own control plane) — documented as a future option but not built yet
- Enterprise SAML (v1.5+)
- Global multi-region (v2.0+)
