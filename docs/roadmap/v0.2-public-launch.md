## Theme: From Beta to Public

v0.1 proved the beachhead: WSL E2E 8/8 PASS, 7 s boot, real Iceberg snapshot. v0.2 is the public launch — the release that goes on the website, gets the GitHub "Star us" campaign, and earns the first 100 external users.

This phase shipped **six** things that matter for the public launch (the original four plus Wave 2 P0 reliability hardening and the v0.2 close-out polish batch):

1. **Workbench v0.3** (shipped) — editorial gradient hero dashboard + 7 interactive pages (Assets / Runs / Schedules / Query / Catalog) with live SSE log streaming, `⌘K` command palette, and offline-first static fallback (works behind corporate proxies). Per [ADR-016](../decisions/ADR-016-workbench-mvp.md) + [ADR-038](../decisions/ADR-038-workbench-v03-interactive-polish.md).
2. **AI Copilot chat in the UI** (shipped) — not just CLI; Workbench-native chat. Per [ADR-015](../decisions/ADR-015-ai-chat-mvp.md). Wraps `litellm==1.83.14`; opt-in `nucleus[ai]`.
3. **Docs site** (shipped) — MkDocs Material build at `docs/site/` (~87 pages, strict-build in CI per [ADR-021](../decisions/ADR-021-mkdocs-material-docs-stack.md)). Public URL `https://nucleus.dev` aspirational pending founder DNS step.
4. **Scheduled assets daemon** (shipped) — `@nucleus.asset(schedule="@daily")` daemon-mode with `nucleus schedule on/off/trigger/list/preview` per [ADR-017](../decisions/ADR-017-schedule-exposure-v01.md). Cross-platform (POSIX `SIGTERM`, Windows `psutil.TerminateProcess`).
5. **Wave 2 P0 reliability hardening** (shipped) — active scheduling daemon + durable run ledger (NDJSON append-only at `.nucleus/runs/runs.ndjson`); cross-platform advisory filesystem lock for concurrent runs (POSIX `fcntl.flock`, Windows `msvcrt.locking`); DuckDB `memory_limit` guard at AMA init surfaces OOM as NE2007; `expire_old_snapshots` post-commit maintenance; verified `os.replace` everywhere. Per [ADR-024](../decisions/ADR-024-reliability-hardening-plan.md).
6. **v0.2 close-out batch** (shipped 2026-05-15) — chaos J3/J8 translate-leak fixes + NE5018 + [ADR-039](../decisions/ADR-039-install-size-split-extras.md) install-size split via extras + perf-doc reconciliation + 6 UX polish wins + governance v0.1→v0.2 LOC bump.

## Features

### Workbench MVP (ADR-016, Fork B)

Per `docs/specs/nucleus_architecture_v4.1.md` §8.1 and [ADR-016](../decisions/ADR-016-workbench-mvp.md):

- React + Vite + TypeScript frontend (Vite for fast HMR)
- Monaco editor (same as VS Code) — asset editing with `@nucleus.asset` syntax awareness
- Asset graph visualizer (xyflow / React Flow) — dependency graph rendered from the project's asset registry
- Chat panel — wraps `nucleus chat` via the same LiteLLM backend as CLI
- FastAPI backend (already scaffolded in v0.1) — serves REST API to the frontend
- Run trigger UI — click-to-materialize individual assets
- Schema browser — inspect asset schema contracts

**What is NOT in Workbench v0.2** (deferred to v0.3+):
- Full schema-aware Copilot completion (needs lineage data — v0.3+)
- Marimo notebook embed (v0.3+)
- Multi-user collaboration (v1.5+)

### Scheduled Assets Daemon (ADR-017)

- `nucleus schedule on <asset-key>` — registers the schedule registered at decoration time
- `nucleus schedule off <asset-key>` — de-registers
- `nucleus schedule trigger <asset-key>` — one-shot manual fire
- `nucleus schedule list` — show all registered schedules + next-run times
- `nucleus schedule preview <asset-key> [--n 5]` — preview next N runs (works in v0.1.1 already)
- Background daemon (`nucleus schedule daemon`) — `croniter`-driven, Dagster-backed scheduler loop

### Connector Batch 2

Per v4.1 §18.2 and the beachhead team's next data sources:

- **BigQuery** (`nucleus ingest bigquery://...`) — via dlt `google_analytics` / BigQuery source; requires `google-cloud-bigquery` extras
- **SFTP / local files** — Parquet and CSV direct ingest (already partially in v0.1 SQLite path; extend to Parquet/CSV without SQLAlchemy)
- **Snowflake read** (`nucleus ingest snowflake://...`) — read-only; Snowflake as a *source* (yield-to-giants Mode 1 complement)

### Docs Site

- Deploy `docs/site/` to `nucleus.dev` (GitHub Pages or Cloudflare Pages)
- Core content: getting-started guide, quickstart, `ctx` SDK reference, CLI reference, connector guides
- API reference auto-generated from docstrings (mkdocstrings or sphinx)

### CI / CD Hardening

- Publish to PyPI via GitHub Actions OIDC (no stored API keys)
- GitHub Release auto-created from `CHANGELOG.md` section
- GitHub Pages deploy for docs on every tag

## Known Risks

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| Workbench frontend scope expands (designer wants more than MVP) | Medium | High | Hard-cut at Monaco + asset graph + chat panel. Anything else is v0.3+. |
| Scheduled assets daemon conflicts with embedded Dagster | Medium | Medium | Daemon uses the same Dagster wrapped substrate; schedule resolution is croniter (already tested). Fallback: mini-scheduler approach if Dagster loop creates issues. |
| Docs site content lag | High | Medium | 5 core pages minimum for launch; defer advanced guides to v0.3. |
| BigQuery connector auth complexity | Medium | Low | BigQuery extras are opt-in (`pip install nucleus[bigquery]`); if auth is a rabbit hole, defer to v0.3 and ship SFTP/CSV only. |
| PyPI publish requires trust setup | Low | Medium | Use GitHub OIDC (no stored secrets). Test `--dry-run` before actual publish. |
