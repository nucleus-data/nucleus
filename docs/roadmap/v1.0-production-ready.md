# v1.0 — Production-Ready

> **Codename**: Production-Ready
> **Target**: 2027 Q3, Month 28-36 (best-case; contingent on Mo 24 decision gate per ADR-002 §8.3)
> **LOC ceiling**: 28,000 (start of phase: ~20,000 from v0.7)
> **Persona**: Startup data team + small enterprise data teams (≤ 200 engineers)
> **Theme**: Small enterprises can run Nucleus in production with confidence. SLA, governance, backups, audit log.

---

## Theme: "Enterprises Can Trust This"

v1.0 GA means:
1. **Stability commitment** — `ctx.*` Frozen-tier APIs get a 2-year deprecation cycle (per ADR-005).
2. **SLA-grade reliability** — Backups, disaster recovery, observability dashboards.
3. **Governance maturity** — Public ADR process, security disclosure SLA, audit log.
4. **Dagster replaceability proven** — `nucleus-mini-scheduler` runs the same project unchanged (per D21, v4.1 §6.5).
5. **First paying customers** — Cloud tier is GA; billing is live.

---

## Features

### 1. `ctx.*` Frozen API Stability (ADR-005)

- All `ctx.copy_from`, `ctx.sql`, `ctx.read` APIs are promoted from Beta to Frozen
- Frozen means: breaking changes require a 2-year deprecation cycle with `NucleusDeprecationWarning`
- `ctx.agent`, `ctx.copilot` remain Beta (per ADR-005 §13.3 — AI APIs evolve faster)
- `check_api_stability.py` enforces Frozen surface in CI

### 2. Dagster Replaceability Proved (D21)

Per `docs/specs/nucleus_architecture_v4.1.md` §6.5 (Decision D21):

- `nucleus-mini-scheduler` implementation (~3,000-5,000 LOC; counted toward 30K ceiling)
- Runs the same `nucleus_project.yaml` unchanged, without Dagster installed
- Triggered by: Dagster Labs license pivot, or >5% users hit Dagster-specific error types
- Validation: every existing test passes with `NUCLEUS_SCHEDULER=mini` env var
- This does NOT mean we ship mini-scheduler by default — Dagster stays the default

### 3. Backup + Disaster Recovery

- `nucleus backup` — exports catalog metadata + generates Iceberg table export manifest
- `nucleus restore` — replays catalog from a backup manifest
- Backups to S3 (cloud tier) or local filesystem (OSS tier)
- Target: RTO < 1 hour, RPO < 24 hours for the beachhead persona (# NEEDS VERIFICATION)

### 4. Observability Dashboards

- `pip install nucleus[observability]` — activates the full OpenTelemetry SDK
- Out-of-box dashboards: asset run latency, error rate per NE-code, MinIO I/O, DuckDB query time
- Works with VictoriaMetrics + Grafana (self-hosted) or any OpenTelemetry-compatible backend
- `scripts/check_otel_wiring.py` — new governance script verifying no telemetry leaks in dry-run mode

### 5. Audit Log

- Every `ctx.*` call, every `nucleus run`, every config change written to `.nucleus/audit.jsonl`
- Tamper-evident (SHA-256 chain; not cryptographic proof but detects accidental overwrites)
- `nucleus audit list` — list events with filters
- Cloud tier: audit log streamed to append-only S3 bucket

### 6. Security Disclosure SLA

- `SECURITY.md` at repo root (already exists per git status)
- 14-day response commitment for CRITICAL, 30-day for HIGH
- CVE reporting path documented
- Security review required for any change to auth paths

### 7. Public RFC Process

- `docs/decisions/` is the ADR repository (already exists)
- For v1.0+: PRs tagged `[RFC]` go through 2-week comment period before merge
- Community can comment on GitHub Discussions

### 8. Polaris Swap Interface + Smoke Tests

Per Composability Constitution (§9.3):

- `pyiceberg.RestCatalog` pointed at Apache Polaris instead of Lakekeeper
- `nucleus enable polaris` — configuration switch
- 5-10 smoke tests: table create, read, snapshot via Polaris
- Full Polaris adapter built on-demand (trigger: if Lakekeeper license/maintenance issue)

### 9. Column-Level Lineage for Python

Per `docs/specs/nucleus_architecture_v4.1.md` §12.4:

- Python-level column lineage: instrument `ctx.read` → transform → `ctx.write` (v0.5 had SQL only)
- Uses Python `ast` module for static analysis of `ctx.read()` call sites (maps input column references to output transformations) combined with lightweight `sys.settrace`-based runtime tracing as fallback for dynamic column selection. Column-level events emitted as OpenLineage `DatasetFacet` using `sqlglot`'s Python AST extension (Tier 0 immortal per v4.1 §4.1). Full design deferred to v0.5+ SQL column lineage stabilisation before Python lineage extends the same schema — per ADR-025 P2-1 and `docs/internal/research/parity_vs_databricks_snowflake.md` §4 P2-1.

## Compatibility Commitment at v1.0

| API tier | Commitment |
|---|---|
| `ctx.*` Frozen | 2-year deprecation cycle before removal |
| `ctx.*` Beta | May break within minor versions with `NucleusAIBreakingChange` warning |
| `nucleus` CLI commands | Stable from v1.0; flags may be added; removal requires minor-version bump + 6-month notice |
| `NucleusError` subclasses | NE-codes are stable; new codes may be added at any minor version |
| `nucleus_project.yaml` format | Stable from v1.0; new fields are optional + backward-compatible |

## What Is NOT in v1.0

- Multi-tenant SaaS at scale (v2.0+)
- Streaming support (v1.5+)
- Data Product Marketplace (v2.0+)
- Self-hosted cloud (v1.5+ enterprise consideration)
- Replay debugger (v1.5+)
- Cost-aware planner (v0.5 has MVP; v1.5 has full version)
