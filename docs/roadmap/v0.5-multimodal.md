# v0.5 — Multimodal

> **Codename**: Intelligence Awakens (internal working title: "Multimodal")
> **Target**: 2027 Q1 (Month 20-28 of founder's timeline)
> **LOC ceiling**: 20,000 (start of phase: ~12,000 from v0.3)
> **Persona**: Startup data team + ML engineer persona added
> **Theme**: Data engineering meets AI engineering. Multimodal data (images, audio, embeddings) becomes first-class. AI Copilot becomes lineage-aware and schema-aware.

---

## Theme: "Data Engineering Meets AI Engineering"

v0.5 is the inflection point where Nucleus becomes useful for AI/ML teams, not just data teams. Three core bets:

1. **Daft (optional)** — multimodal engine for large-scale image/audio/embedding workloads.
2. **Lance / LanceDB (optional)** — vector + multimodal storage alongside Iceberg structured storage.
3. **AI Copilot 2.0** — lineage-aware, schema-aware, project-context-aware. The Copilot can reason about your asset graph.

## Features

### 1. `ctx.agent` Runtime (Sandboxed AI Code Generation)

Per `nucleus_architecture_v4.1.md` §7.3:

```python
from nucleus import agent

agent.scaffold_pipeline(
    description="Ingest Stripe charges nightly, build daily revenue rollup, expose to BI",
    target_dir="assets/finance/",
)
```

**Behavior**:
1. LLM proposes asset code (`@nucleus.asset`, `@nucleus.source`, `@nucleus.sql_asset`)
2. Code written to sandbox branch, NOT committed
3. Tests auto-generated and run in subprocess
4. User reviews diff in Workbench
5. User approves → merged to project

**Guardrails** (non-negotiable):
- Agent cannot modify Tier 0 standards or core configs
- Agent cannot commit without explicit human approval
- Agent cannot access production secrets
- All agent actions logged in audit trail

**Stability tier**: Beta throughout v0.5 (per ADR-005; AI APIs evolve faster than core data APIs)

### 2. Nucleus MCP Server (~500 LOC)

Per `nucleus_architecture_v4.1.md` §7.3 + ADR-002 §4.2:

- `nucleus-mcp-server` exposes assets / contracts / lineage to MCP-compatible AI agents via `ctx`
- Any MCP-compatible host (Claude desktop, Cursor, custom agent) can query Nucleus's asset graph
- This is an **additive thin adapter** — does NOT pivot Nucleus into "agent data substrate" category
- Per ADR-002: this is a hedge against the agent-substrate scenario, not a category definition

### 3. Daft (Optional Multimodal Engine)

- `pip install nucleus[multimodal]` enables Daft
- `@nucleus.asset(engine="daft")` — routes the asset body through Daft for multimodal processing
- Use cases: image transforms, audio feature extraction, embedding generation from unstructured data
- Daft produces Arrow-compatible outputs → can write to both Iceberg (structured) and Lance (vector)
- Docs: https://www.getdaft.io/projects/docs/en/stable/

### 4. Lance / LanceDB (Optional Vector + Multimodal Storage)

- `pip install nucleus[lance]` enables Lance
- `@nucleus.asset(format="lance")` — writes to Lance columnar format instead of Iceberg Parquet
- Lance format is Tier 0 immortal (ASF-inspired governance, open spec)
- Use cases: embedding storage, image thumbnails, multimodal features alongside structured data
- Lance files sit in the same `data/` warehouse directory as Iceberg tables
- Docs: https://lancedb.github.io/lance/

### 5. AI Copilot 2.0 — Schema-Aware + Lineage-Aware

Per `nucleus_architecture_v4.1.md` §7.2:

- Copilot now has access to the full asset graph (via lineage NDJSON + asset registry)
- Context window includes: upstream/downstream asset schemas, historical run results, contract violations
- In Workbench: Copilot can suggest schema changes, explain lineage, generate SQL from natural language
- New `ctx.copilot` API (Beta tier): `ctx.copilot.explain(asset_key)`, `ctx.copilot.suggest_check(asset_key)`

### 6. Column-Level Lineage for SQL

Per `nucleus_architecture_v4.1.md` §12.4:

- `sqlglot` (already in `[lineage-advanced]` extras) used to parse `ctx.sql` queries
- Column-level lineage extracted: "column X in asset B came from column Y in asset A"
- Stored in extended OpenLineage events (column-level facets)
- Displayed in Workbench lineage graph as column-to-column edges

### 7. Cost Meter MVP

Per `nucleus_architecture_v4.1.md` §7.5:

- Pre-run cost estimate: CPU-seconds, S3 GETs, egress, AI tokens → dollars per run
- `nucleus run --estimate` — shows estimate without running
- `nucleus run --cost-limit 5.00` — aborts if estimate exceeds limit
- Per-asset cumulative cost tracking in `.nucleus/cost_history.jsonl`

### 8. `ctx.snapshot()` and Incremental Materialization

- `ctx.snapshot(asset_key, as_of=datetime)` — load asset as of a point in time
- `@nucleus.asset(materialization="incremental")` — only processes new rows since last run
- Iceberg partitioning used for efficient incremental reads

## Yield-to-Giants Mode 2 Deepening

Per `nucleus_architecture_v4.1.md` §10.2:

- `@nucleus.asset(compute="databricks")` — dispatches heavy compute to Databricks
- `@nucleus.asset(compute="snowflake")` — dispatches SQL assets to Snowflake
- Nucleus handles the dispatch, auth, and result materialization back to Iceberg
- User code unchanged; only the `compute=` kwarg added

## What Is Intentionally NOT in v0.5

- Streaming support (v1.5+)
- Multi-tenant Cloud (v0.7 is single-tenant only)
- Enterprise RBAC / SAML (v1.5+)
- LLM training or model serving (never — out of scope per `AGENTS.md §4`)
