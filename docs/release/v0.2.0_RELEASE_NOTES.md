# Nucleus v0.2.0 — Public Launch

> *Curated body for `gh release edit v0.2.0 --notes-file docs/release/v0.2.0_RELEASE_NOTES.md` after `.github/workflows/release.yml` auto-creates the GitHub Release. Strict Nucleus vocabulary per AGENTS.md §7.*

---

## TL;DR

**Nucleus ships data products from a laptop.** v0.2.0 is the first publicly available release: a local-first Python SDK + CLI for building Iceberg-native pipelines and analytics stacks, AI-ready by design, that graduates cleanly to any Iceberg catalog (Polaris, Lakekeeper, Unity, R2, Snowflake-Iceberg-compat) when teams outgrow their laptop. Wraps DuckDB, Polars, Apache Iceberg (via pyiceberg), and embedded orchestration (Dagster, hidden behind `ctx`) into one `pip install nucleus`. Apache 2.0. No JVM in the default path. `git clone` to first BI-ready Iceberg table in <30 minutes per the [empirical WSL beachhead E2E](../benchmarks/2026-05-15_baseline.md).

---

## Highlights

- **8-command CLI** — `init / up / down / run / ingest / query / chat / version`. Every error is a stable `NE####` code with a `docs_url`; zero wrapped-library classnames in user-facing strings (enforced in CI).
- **Seven source connectors via one `ctx.copy_from()` dispatcher** — Postgres, MySQL, SQLite, Snowflake, S3, GCS, local filesystem (Parquet/CSV/JSON with auto-detect + glob). Optional extras `nucleus[postgres|mysql|snowflake|s3|gcs]` keep the lean core under 30 deps.
- **Workbench v0.3** — editorial gradient hero dashboard + 7 interactive pages (Assets / Runs / Schedules / Query / Catalog) with live SSE log streaming, `⌘K` command palette, and offline-first static fallback (works behind corporate proxies).
- **Active scheduling daemon + durable run ledger** — `@nucleus.asset(schedule="@daily")` now executes on schedule. `nucleus runs list/show/cancel/tail` exposes a thread-safe append-only NDJSON ledger at `.nucleus/runs/runs.ndjson`. Cross-platform (POSIX `SIGTERM`, Windows `psutil.TerminateProcess`).
- **Iceberg branch + tag CLI + `nucleus.db` BI handshake** — `nucleus snapshot branch/tag` exposes pyiceberg's `manage_snapshots()` for compliance archiving. `nucleus up` now writes a single-file DuckDB at `nucleus.db` so Superset / Evidence / Rill / Streamlit connect via one path.
- **Reliability hardening (Wave 2 P0-1/P0-2/P0-3)** — DuckDB `memory_limit` guard at AMA init (OOM surfaces as `NE2007`); cross-platform advisory filesystem lock for concurrent runs; `expire_old_snapshots` post-commit maintenance; verified `os.replace` everywhere (no `os.rename` on Windows).
- **Public docs site + uv toolchain** — ~55-page MkDocs Material site (strict-build in CI); `astral-sh/setup-uv@v3` replaces `pip install` (~2 m 15 s → ~8 s); ruff 0.15.13 (ADR-027); 11-script governance suite enforced in CI.

## Try it now

```bash
pip install nucleus               # core only (~16 deps, <60 s install on warm pip cache)
nucleus init my-stack && cd my-stack
nucleus up && nucleus run example.greeting
```

For Postgres ingestion + Workbench:

```bash
pip install "nucleus[postgres,workbench]"
nucleus init my-stack && cd my-stack && nucleus up
nucleus ingest postgres://localhost/app --table public.orders --as raw.orders
nucleus query "SELECT count(*) FROM {{ ref('raw.orders') }}"
nucleus workbench up                     # http://localhost:8765
```

## What's NOT in v0.2.0 (deferred, on the roadmap)

- **Lakekeeper REST catalog** — v0.3+ (ADR-004); v0.2 stays on filesystem catalog. Bytes on disk are valid Iceberg snapshots, so any catalog can re-register them later.
- **dbt-duckdb adapter** — v0.3+ optional integration. v0.2 ships native `ctx.sql` + Jinja `{{ ref() }}` resolver (~180 LOC, hard 2,500 LOC scope ceiling per architecture v4.1 §5.6.0).
- **Marimo notebook integration** — v0.3+. v0.2 ships no notebook runtime.
- **Column-level lineage** — v0.5+ for SQL (via sqlglot under `nucleus[lineage-advanced]`); v1.0 for Python. v0.2 ships asset-level OpenLineage NDJSON only.
- **Lineage-aware AI Copilot** — v0.5+. v0.2 ships chat-only via `nucleus chat` (wraps `litellm==1.83.14`; opt-in `nucleus[ai]`).
- **`nucleus-mcp-server`** — v0.5+ (ADR-030). **Daft + Ray + vector storage** — v0.5+ yield-to-giants.
- **Full WAP (write-audit-publish)** — v0.3+ pending Lakekeeper branch-targeted writes. Branch + tag *CLI* surface ships in v0.2 as Beta.

## Breaking changes

This is the first public release. v0.1.0 was an internal beta two days ago (no PyPI artifact, no external users). The `ctx` SDK signatures locked in v0.1.0 are unchanged in v0.2.0. **No breaking changes for external users.**

## Known issues (honest disclosure per AGENTS.md §10.8)

- **Boot time empirical**: ~2.0 s on a contention-loaded host vs the <500 ms target in `docs/research/performance_reliability_targets.md`. Targets doc demoted to "v0.3 targets / v0.2 actuals" per Anti-Over-Engineering default. The 30-min beachhead metric is unaffected.
- **Concurrent-run safety on Windows**: chaos B4 FAILS on Windows. NTFS `msvcrt.locking` byte-range semantics differ from POSIX `fcntl.flock`; Linux + WSL pass. Use WSL until v0.2.1 if you need concurrent `nucleus run` on the same asset.
- **Materialize 10 GB**: peaks at 8.4 GB RAM vs the 6 GB target. The `memory_limit` guard prevents OOM but the high-water mark is real.
- **macOS native untested at user scale**: CI runs on `macos-latest`, but zero external macOS testers in the v0.1/v0.2 cycle. PoC #5 closes this gap.
- **`v0.1.0` git tag not published** — internal beta, no PyPI artifact (per close-out checklist Option B).

Full empirical numbers: [`docs/benchmarks/2026-05-15_baseline.md`](../benchmarks/2026-05-15_baseline.md). All 11 deltas documented honestly rather than re-run until they pass.
