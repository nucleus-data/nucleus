# Nucleus v0.2.0 Launch Risk Register

> Last updated 2026-05-16. This register is the launch-day truth source for go/no-go discipline. Canonical repo: <https://github.com/nucleus-data/nucleus>. Public docs home: <https://nucleus-data.github.io/nucleus/> once GitHub Pages is enabled; Pages requires the repo to be public or GitHub Pro until then.

| # | Risk | Severity | Probability | Detection signal | Mitigation | Owner | Go/no-go status |
|---|---|---|---|---|---|---|---|
| 1 | Canonical repo URL split sends users to the legacy personal remote | Critical | Medium | Search launch-critical docs for the legacy personal repo URL | Use `https://github.com/nucleus-data/nucleus` in launch-critical docs; preserve legacy only when explicitly historical. | Founder | MUST PASS |
| 2 | PyPI Trusted Publisher is not registered before tag push | Critical | Medium | Release workflow fails at `publish-pypi` with OIDC publisher error | Register owner `nucleus-data`, repo `nucleus`, workflow `release.yml`, environment `pypi`; re-run failed workflow, do not re-tag. | Founder | MUST PASS |
| 3 | GitHub Release is created twice | Critical | Medium | `release.yml` has `Create GitHub Release`; runbooks also say `gh release create` | Founder action is tag push, then verify workflow-created release; manual `gh release create` is fallback only if the workflow did not create a release. | Founder | MUST PASS |
| 4 | PyPI package name `nucleus` is unavailable | Critical | Low | `curl -fsSI https://pypi.org/project/nucleus/` returns an existing unrelated project before publish | Stop before tag, decide fallback package name, update `pyproject.toml`, and rerun release gates. | Founder | MUST PASS |
| 5 | Public install copy overclaims availability before PyPI publish | High | High | README or quickstart implies `pip install nucleus` works before the tag workflow succeeds | Distinguish pre-PyPI local dev (`pip install -e ".[dev]"`) from public release install after PyPI publish (`pip install nucleus` plus extras). | Founder | MUST PASS |
| 6 | Workbench port inconsistency breaks demo copy | High | Medium | Docs mention a non-default Workbench port as the default user URL | Use actual CLI default `localhost:8765` from `src/nucleus/workbench/cli.py` and `src/nucleus/cli/commands/workbench_cmd.py`. | AI docs worker | MUST PASS |
| 7 | Launch kit contains raw placeholders | High | High | Search `docs/release/launch_kit` for unresolved angle-bracket placeholders | Replace placeholders with concrete founder actions or Workstream C asset actions; do not fake screenshots. | Founder + Workstream C | MUST PASS |
| 8 | Screenshot/demo assets are absent but treated as done | High | Medium | `assets/demos/v0.2/launch_60s.mp4` or `assets/screenshots/v0.2/*` missing | Checklist marks screenshots and demo as go/no-go items; Workstream C owns capture and upload. | Workstream C | MUST PASS for media-heavy channels |
| 9 | Self-upvote or engagement manipulation appears in HN instructions | High | Medium | `rg -i "self-upvote|upvote|vote-ring" docs/release/launch_kit` | Remove self-upvote instructions; keep only anti-manipulation warnings and good-faith response guidance. | Founder | MUST PASS |
| 10 | CI is red on `main` at launch time | Critical | Medium | `gh run list --workflow=ci.yml --branch=main --limit=1` not `success` | Defer launch, fix the root cause, rerun CI, then restart go/no-go check. | Founder | MUST PASS |
| 11 | Governance scripts fail locally | Critical | Low | `check_vocabulary.py` or `dagster_leak_check.py` exits non-zero | Fix docs/source drift before tag; do not waive vocabulary or error-translation gates. | Founder | MUST PASS |
| 12 | Benchmark gaps are hidden or over-marketed | High | High | Public copy omits `docs/benchmarks/2026-05-15_baseline.md` known failures | Lead with honest beta framing: 11 measured deltas, Windows concurrent-run gap, and v0.2.1 follow-up. | Founder | MUST PASS |
| 13 | Windows concurrent-run failure becomes an HN credibility hit | High | Medium | HN/Reddit asks about B4 Windows failure or a user reproduces it | State Linux/WSL passes, Windows same-asset concurrent writes are not launch-safe, v0.2.1 tracks the fix. | Founder | SHOULD PASS |
| 14 | Press kit stats disagree with final governance output | High | Medium | `loc_budget.py`, release notes, press kit, and README report different LOC/test counts | Use final command outputs in release notes and press kit; if not remeasured, mark as pending remeasurement. | Founder | SHOULD PASS |
| 15 | Public docs site is unreachable | High | Medium | <https://nucleus-data.github.io/nucleus/> returns 404/403 | Either make repo public/enable Pages or route users to README + `docs/onboarding/quickstart.md`; do not announce a dead docs URL. | Founder | MUST PASS for docs link |
| 16 | GitHub branch protection cannot be applied before launch | Medium | Medium | GitHub Pro/Team unavailable or rules API fails | Document as deferred; do not block launch if CI is green and tag push remains founder-gated. | Founder | OK TO DEFER |
| 17 | Show HN gets hostile "wrapper" criticism | Medium | High | Multiple comments say "just dbt/Dagster/DuckDB" | Respond with wrap-not-build thesis, LOC ceiling, error namespace, and Iceberg graduation path; do not over-defend. | Founder | SHOULD PASS |
| 18 | Security report arrives in first week | Critical | Low | Issue/email flags credential leak, RCE, data loss, or dependency CVE | Acknowledge within 24 h, move details out of public thread if sensitive, cut v0.2.1 if confirmed. | Founder | MUST PASS post-launch |
| 19 | Support triage overwhelms founder | Medium | Medium | >10 issues/discussions in first 24 h or repeated install failures | Label `installation broken`, `bug`, `question`, `docs`; prioritize install failures and data-loss reports. | Founder | SHOULD PASS |
| 20 | Post-launch feedback is not captured for v0.2.1 | Medium | High | HN/Reddit/GitHub comments remain scattered with no synthesis | Maintain `FIRST_7_DAYS_PLAYBOOK.md` triage log and fold recurring pain into v0.2.1 scope. | Founder | SHOULD PASS |

Verdict rule: any open `MUST PASS` item is **NO-GO** for public announcement. `SHOULD PASS` items can ship only with explicit caveats in `GO_NO_GO_CHECKLIST.md`. `OK TO DEFER` items must have an owner and a target release.
