## Context

Nucleus materialises assets to Iceberg+MinIO but has no mechanism to connect external BI tools (Superset, Rill, Evidence, Streamlit) to those assets out-of-the-box. Users currently must understand Iceberg REST catalog URIs and DuckDB extension syntax before they can visualise data — a >30-minute setup burden that violates the beachhead metric.

Two complementary outputs close this gap:

1. **`nucleus.db`**: A DuckDB file generated by `nucleus up` containing `CREATE OR REPLACE VIEW` statements backed by `iceberg_scan()` for every materialised asset. Any DuckDB-compatible BI tool connects with a single file path — zero configuration.
2. **`<asset>_metrics_view.yaml`**: A Rill-compatible descriptor auto-generated by `nucleus run <asset>` from the asset schema (numeric columns → candidate measures; low-cardinality columns → dimensions). Launching `rill dev` after a `nucleus run` takes < 5 seconds.

Research evidence (R7 §5): Superset has official DuckDB support with catalog browsing since April 2025 (PR #28751). Rill reads an external DuckDB file directly via `path: '/path/to/nucleus.db'` with zero additional configuration (R7 §1). Evidence.dev DuckDB connection requires one YAML edit (R7 §2). Streamlit pattern is documented and confirmed (R7 §6).

## Options Considered

| Option | Description | Reason considered/rejected |
|---|---|---|
| **A — DuckDB file + Rill YAML** | Emit `nucleus.db` on `nucleus up`; emit `<asset>_metrics_view.yaml` on `nucleus run` | ✅ SELECTED — ~200 LOC total; covers all 4 major BI tools; aligns with beachhead metric |
| B — Iceberg REST catalog docs only | Document how users can manually connect BI tools | ❌ REJECTED — manual setup > 30 min; misses beachhead metric |
| C — Separate nucleus.db and metrics YAML ADRs | Two separate ADRs for the two outputs | ❌ REJECTED — same trigger event, same PR; over-engineering (Anti-Over-Engineering Discipline) |

## Decision

Ratified 2026-05-15: implemented in commit a41a82c (v0.2.0 workstreams bundle).

**Option A implemented.** `nucleus.db` is generated by `nucleus up` using pyiceberg Arrow scan
to write materialized asset snapshots as native DuckDB tables (self-contained, no iceberg
extension required). Connect string: `duckdb:////<project_root>/nucleus.db`.
Cookbook: `docs/cookbook/bi-connectivity.md`.

Note: DuckDB iceberg extension (`iceberg_scan()` live views) requires network download —
documented in cookbook as "advanced" option. Default implementation uses Arrow snapshot
tables (works fully offline).

**[PLACEHOLDER — awaiting founder ratification]**

Recommended: **Option A**. Both outputs ship in a single PR (~200 LOC, v0.2 milestone).

Key implementation notes:
- `nucleus.db` ATTACH syntax: verify `ATTACH ... TYPE ICEBERG` exact syntax before implementation (R7 NV-6: https://duckdb.org/docs/current/core_extensions/iceberg/iceberg_rest_catalogs.html).
- Metrics YAML: auto-infer `timeseries` column from the first `timestamp`/`date` column in schema; skip if no time column.
- Do NOT hard-code Rill-specific semantics in the measure inference — the YAML format is compatible with MetricFlow (v0.3, ADR-029) by design.
