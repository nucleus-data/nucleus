# Homebrew packaging — founder runbook

This directory contains the **draft** Homebrew formula for the `nucleus` CLI on macOS (and Linuxbrew).

## Two distribution paths

| Path | Time-to-live | Trade-off | Recommended for v0.2.0 |
|---|---|---|---|
| **Custom tap** (`nucleus-data/homebrew-nucleus`) | Immediate (we own the tap) | Users must run `brew tap nucleus-data/nucleus` once | YES — ship day-1 |
| **Homebrew-core** (the default tap, no `tap` step) | 1-7 days review queue | Visible in `brew search nucleus`; community trust | Submit AFTER tap is live + we have ~10 weeks of stable releases |

**Default for v0.2.0**: ship the tap first. Submit to `homebrew-core` only after the project clears the [homebrew-core acceptance criteria](https://docs.brew.sh/Acceptable-Formulae) — most importantly, **30 GitHub stars + 30 forks + 30 watchers** AND a release history showing maintained cadence. v0.2.0 will not meet this bar; revisit at v0.5+.

See `tap_setup.md` in this directory for step-by-step tap creation.

## Pre-publish checklist (founder, every release)

1. **PyPI is live first.** The formula's `url` field points at a GitHub release tarball, but the wheel installation pipeline ultimately resolves via PyPI. Confirm `pip install nucleus-data` works from a clean venv (see `../pypi/PUBLISH_RUNBOOK.md` Step 6).

2. **Compute the source tarball SHA256.** After tagging `v0.2.0`, GitHub auto-generates `https://github.com/nucleus-data/nucleus/archive/refs/tags/v0.2.0.tar.gz`. We instead use the *release* asset (`releases/download/v0.2.0/nucleus-data-0.2.0.tar.gz`) which is the sdist we built from `python -m build`. Compute its hash:

   ```bash
   curl -sL https://github.com/nucleus-data/nucleus/releases/download/v0.2.0/nucleus-data-0.2.0.tar.gz \
     | shasum -a 256
   ```

   Paste the result into `nucleus.rb` line `sha256 "..."`.

3. **Regenerate Python resource blocks.** Homebrew-core requires every transitive dep to appear as a `resource` block. Use `homebrew-pypi-poet` (one-time install: `pipx install homebrew-pypi-poet`):

   ```bash
   pipx run --spec homebrew-pypi-poet poet --formula nucleus-data > /tmp/nucleus-resources.rb
   ```

   Replace the `===== POET-GENERATED-START =====` ... `===== POET-GENERATED-END =====` block in `nucleus.rb` with the output. Expect ~80-100 `resource` entries (the core deps are 16 direct, but they pull in ~80 transitives).

4. **Audit locally.**

   ```bash
   brew audit --strict --new --online ./packaging/brew/nucleus.rb
   brew install --build-from-source ./packaging/brew/nucleus.rb
   nucleus --version
   brew uninstall nucleus
   ```

   `brew audit --strict` flags style violations, missing license, broken URLs, and obsolete macOS APIs. Must be clean before tap push.

5. **Push to the tap.** See `tap_setup.md`.

## Submitting to homebrew-core (DEFER until v0.5+)

When the founder is ready (months from v0.2.0):

1. Confirm acceptance criteria: https://docs.brew.sh/Acceptable-Formulae — needs 30★ + 30 forks + 30 watchers, no "we just released" status.
2. Fork https://github.com/Homebrew/homebrew-core.
3. Add `Formula/n/nucleus.rb` (the audited formula).
4. PR with title `nucleus 0.2.0 (new formula)`.
5. Maintainers respond in 1-7 days; expect at least one round of review feedback (typical asks: split very large `resource` blocks, prove the test block actually exercises the binary, justify any non-Python build deps).

The custom tap stays alive after homebrew-core acceptance — users who already `brew tap`'d don't need to migrate, and version cadence in the tap can outpace homebrew-core's review queue.

## Known limitations

- **Apple Silicon (arm64) + macOS x86_64**: pyiceberg, polars, duckdb, pyarrow all ship pre-built wheels for both arches; no special handling needed in the formula. Confirm by `brew install --build-from-source ./packaging/brew/nucleus.rb` on both arches.
- **Linuxbrew**: should work with the same formula but is untested. Ubuntu users are better served by `pip install nucleus-data` directly.
- **Bottle generation**: a "bottle" is a pre-built binary tarball Homebrew uploads to its CDN so users don't rebuild from source. We do **not** ship bottles in v0.2.0 — installs will rebuild from source (~30-60 s on a modern machine, mostly the wheel download for polars/pyarrow). Bottles get auto-generated by Homebrew CI when a formula lands in homebrew-core; for our own tap we'd need [GitHub Actions bottle building](https://docs.brew.sh/Bottles), which is a separate ~1 day task.
